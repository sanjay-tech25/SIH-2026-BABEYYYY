# UI audit and Genie motion

Reviewed September 22, 2026. Scope: the existing React application, its 15 views, shared navigation, overlays, and interactive content. The requested effect is macOS-inspired Genie motion, preserving the existing visual design.

## Findings and changes

| Area | Finding | Change |
| --- | --- | --- |
| Page navigation | One generic upward fade; a permanent transform hint created a containing block for fixed descendants | Shared, restrained perspective entrance; no permanent transform hint |
| Floating panels | Conditional rendering removed panels immediately on close | Real content remains mounted for the exit, becomes inert, then unmounts |
| Notification and mobile navigation panels | No consistent entrance or exit | Panels unfold from their trigger and contract back toward it |
| Companion | The expanded panel continuously floated, including while reading or using its timer | Anchored Genie opening/closing; stationary reading surface and animated mode changes |
| Studio | Preset dropdown, expandable grid, and toast used unrelated or undefined animation utilities | Shared presence animation, content transitions for gate filters and answer modes, toast above the companion |
| Learning path | Lessons appeared/disappeared abruptly | Reversible unfolding of milestone details |
| Motion accessibility | Reduced Motion only updated local checkbox state | App-wide persisted preference, combined with system reduced-motion preference |
| Keyboard behavior | Panels disappeared without consistently returning focus | Focus returns to the trigger when a focused panel closes; closing content cannot receive keyboard or pointer input |
| Authentication | Existing dialog callback was unused by the landing page | Small Sign in action connects the existing callback; animated dialog, Escape close, focus trap, and scroll locking |
| Responsive navigation | Full navigation became cramped at laptop widths | Compact menu below 1536px; viewport-limited menu height |
| Navbar contrast | `/92` background opacity was not generated by Tailwind | Valid arbitrary opacity restores the intended plum background |
| Mobile overlays | Fixed widths could extend past narrow screens | Bounded companion, notifications, preset menu, and dialog dimensions |

Existing circuit simulation, gate drag/drop feedback, canvas rendering, and quantum calculations remain separate from the interface motion system. Genie is a CSS approximation using tapered clipping and nonuniform scaling, rather than a pixel-for-pixel reproduction of macOS window deformation. Full panels use the stronger effect; reading content uses shorter, subtler entrances.

## Implementation

- `components/ui/GenieMotion.tsx`: provider and reusable presence component.
- `components/ui/useGenieMotion.ts`: preference context, presence lifecycle, anchor measurement, scroll reveals, stagger helper.
- `index.css`: shared keyframes, directional taper, action feedback, and motion overrides.
- Opening lasts 520ms; closing lasts 380ms, with a 460ms fallback cleanup. Content enters over 420–460ms. No animation dependency was added.
- The reduced-motion preference is saved under `quanta-reduced-motion`. System reduction takes precedence. This controls interface effects and CSS animation; it does not stop every existing JavaScript canvas simulation loop.

## Verification

- Production Vite build passes.
- ESLint passes for both new motion modules without warnings.
- Independent review found no significant motion lifecycle regressions.
- In-app browser checks: all ten primary navigation views, lesson feedback, practice hint/answer/next-question flow, results rendering, onboarding forward/back with retained name, and public landing page.
- Panel checks: entrance/exit states, rapid reopen while closing, inert closing content, focus restoration, preset search and selection, grid collapse/reopen, and spatial viewer open/close.
- Accessibility checks: app preference disables Genie immediately and survives reload; sign-in traps Tab/Shift+Tab, closes with Escape, restores focus, and releases scroll locking.
- Responsive checks: 320px and 390px mobile panels, laptop layout, 1600px desktop navigation, and dark-theme notification motion.

## Existing limitations outside this motion change

- Strict project TypeScript checking is not clean: many existing unused imports/variables remain. With unused checks disabled, an existing undefined `targetIdx` remains in `ARVRQuantumViewer.tsx` inside the gate interpolation completion callback.
- Authentication submission, external Colab launches, backend AI responses, camera access, and headset hardware were not exercised by this UI verification.
- Some legacy controls and scientific canvases have their own accessibility and animation behavior; this is not a full WCAG conformance assessment or a frame-rate benchmark.
- The repository already contained extensive uncommitted UI changes. Those edits were preserved; this audit describes the added motion work, not the entire working-tree diff.
